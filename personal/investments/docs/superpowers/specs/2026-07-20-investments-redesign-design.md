# Investments Page Redesign

## Problem

The current single "Ledger" page (`notes/index.html`, generated by the bun pipeline) does not serve its purpose. The owner wants three things from it:

1. Awareness of **contributions across all accounts**.
2. Understanding of **growth**.
3. **Expected tax implications for the current year**.

Concrete complaints:

- The date-range control is a pair of month inputs, not a real calendar range picker.
- Charts are hand-rolled SVG. Tooltips either do not appear or track the cursor at the wrong position (the `viewBox="0 0 1000 300"` with `preserveAspectRatio="none"` stretch plus mismatched hover index math).
- The page shows a wall of filters and a pile of figures without organizing around what the owner actually cares about.
- "Growth beyond contributions" is misleading: it is `cost basis − contributions` (transfers and reinvested income), not real investment gains, because the source data has no market values.

Additionally, five sibling HTML pages (`contributions.html`, `growth.html`, `cash-flow.html`, `holdings.html`, `income.html`) are dead orphans from an earlier version; only `index.html` is generated now.

## Data reality (constraints)

The pipeline reads Wealthsimple monthly statement **transactions** (`data/datastore.json`: `meta`, `accounts`, `transactions`). Per holding it derives `symbol`, `qty`, and `acb` (adjusted cost base). There are **no market values** anywhere in the source.

- `buildLedger` currently drops every non-CAD transaction (`if (txn.currency !== "CAD") continue`), so the USD non-registered account is invisible. The price/FX work fixes this.
- Realized capital gains are derivable: the existing `applyTrade` already tracks average cost, so a SELL's proceeds minus average ACB gives the realized gain.
- True historical market-value-over-time is **out of scope**: it would require per-month historical prices reconstructed against positions. Market value is therefore a **current snapshot**, labeled "as of <date>". Cost basis and contributions keep their monthly history.

## Approach

Chosen: **three-pillar dashboard on one scrolling page** (approach A). One self-contained offline HTML file, reorganized around the three goals, driven by a single smart filter. Rejected: tabbed views (hides cross-pillar context, fiddly state in a static file) and minimal patch (does not fix the core organization complaint).

## Pipeline changes (`scripts/src/`)

Pipeline today: `parse → classify → mask → datastore → analytics → render`, driven by `build.ts`.

### New stage `prices.ts` (after `analytics`, before `render`)

- Input: the holdings list (`symbol`, `qty`, owning account currency).
- Fetches **current** prices:
  - Equities / ETFs: free no-key source (Stooq CSV quote, e.g. `https://stooq.com/q/l/?s=<sym>.us&f=sd2t2ohlcv&e=csv`).
  - Crypto: free no-key source (CoinGecko simple price).
  - One **USD→CAD FX** rate (Frankfurter / exchangerate host, no key).
- Sources are isolated behind a small interface so they are swappable.
- Output: `data/prices.json` — `{ symbol, price, currency, asOf }[]` plus the FX rate and a fetch timestamp.
- **Failure handling**: on network failure or unknown symbol, fall back to that holding's cost basis and mark it `priced:false`. The disk cache (`data/prices.json`) is reused when a build runs without network, so a build never hard-fails on prices.
- `prices.test.ts` mocks fetch and asserts: quote parse, crypto parse, FX application, unknown-symbol fallback, cache reuse.

### Extend `analytics.ts`

Add three derived blocks to the `ledger` object (keep existing `series`, `limits`, `holdings`):

- `growth`: per-account and total **market value** (`qty × price × fx`), **cost**, **unrealized gain**, **unrealized %**, and a `priced` coverage flag (share of cost that is genuinely priced vs fallen back to cost). Unpriceable holdings (e.g. PE/private) sit at cost and are flagged.
- `tax`:
  - Per registered group (TFSA, FHSA, RRSP, RESP): room used / limit / remaining by year, **over-contribution flag**, and RRSP deduction available.
  - Per taxable (non-registered / crypto / DI / PE) account: **YTD interest**, **eligible vs non-eligible dividends** (best-effort split from transaction type/description; unknown defaults to eligible with a note).
  - **Realized capital gains YTD**: SELL proceeds minus average ACB, aggregated for the current year, taxable accounts only.
  - A rough **estimated tax added this year**: interest ×100%, eligible dividends grossed up ×1.38 then dividend tax credit, non-eligible ×1.15, capital gains ×50% inclusion, minus RRSP deduction, times an **editable marginal rate** (client-side input; a sensible Quebec default). Explicitly a rough estimate, never a filing number.
- Each block is a pure function over `Datastore` + `prices.json`, with its own `.test.ts` (room math, dividend split, realized-gain math, estimate math).

## Page structure (`render.ts` + client)

One scrolling page, sections in priority order:

1. **Contributions & Room** — headline (total contributed; this-year room used across registered accounts); per-group room bars with over-contribution warnings; contributions-over-time chart.
2. **Growth** — market value vs cost with unrealized gain %, labeled "as of <date>"; capital / contribution trend over time; top movers by unrealized gain; a coverage note when some holdings are unpriced.
3. **Tax this year** — taxable income (interest + dividends), realized capital gains, estimated tax added (editable marginal rate), with a visible "rough estimate, not for filing" disclaimer.
4. **Detail** (collapsible) — accounts table + holdings table, tidied.

All sections derive from one resolved month-range + account set, preserving the existing single-source `resolveMonths` / `selected` pattern so every section filters together.

## Filter component

Replace the always-open filter bar with a **collapsed scope summary** (e.g. "All accounts · Last 12 months") that opens a popover:

- Account picker grouped by **Registered / Taxable / Cash**.
- Preset chips: YTD / 1Y / 3Y / All.
- **flatpickr** range calendar for custom ranges.

The three input groups stay mutually exclusive (touching one resets the others) so the active window is never ambiguous.

## Libraries (vendored, bundled into the page)

- **Chart.js** for all charts — reliable built-in tooltips with correct hit-testing; replaces hand-rolled SVG and fixes the tooltip bug at the root.
- **flatpickr** (range mode) for the calendar.
- Both added as deps and **bundled by `build.ts` into the emitted `index.html`** so the page stays a single offline file (consistent with the self-hosted fonts). No CDN.

## Cleanup

- Delete the five dead orphan pages (`contributions/growth/cash-flow/holdings/income.html`).
- Rewrite `src/ledger.js` as the new client. Convert to TypeScript if it bundles cleanly through the existing build; otherwise keep as a bundled JS entry.

## Testing / verification

- Unit tests: `prices` (mocked fetch, FX, unpriceable fallback, cache reuse), growth math, tax math (room, dividend split, realized gains, estimate).
- `bun run check` (biome + tsc + bun test) green; zero warnings.
- Drive the built page in a browser (Playwright) to confirm tooltips track the cursor and the range picker filters every section together.

## Non-goals

- No historical market-value reconstruction (current snapshot only).
- No actual tax filing figure; the projection is a clearly labeled estimate.
- No change to the parse/classify/mask/datastore stages beyond what growth/tax derivation needs.
- No CDN dependencies; everything stays offline and self-contained.
